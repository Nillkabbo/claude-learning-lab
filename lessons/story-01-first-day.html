Chapter 1 of 12 — the story so far.

Monday, 9:04 a.m.

The desk has someone else's coffee rings on it. Priya — your lead, you learned her name forty minutes ago — drops a laptop on the table and doesn't sit down.

"So. We keep losing track of small tasks. Tickets live in three places, none of them real. I want a tiny command-line tracker. tracker add, tracker list, tracker close. That's the whole product."

"By when?"

"Demo Thursday. It doesn't have to be pretty. It has to work." She points at the laptop. "Also — install Claude Code. If you're not twice as fast as the last person by month two, we hired wrong." And she's gone.

You look at the empty repository. Then at the install command.

The tool arrives

curl -fsSL https://claude.ai/install.sh | bash
claude --version

Native install — it'll keep itself updated. You run claude in a fresh folder called tracker, and a browser opens: you sign in with your account (a subscription, if you have one — or pay-as-you-go Console credits; the quickstart lists the options). Credentials persist. You're in.

A prompt blinks. This is the moment most beginners waste: they type something like "make me a tracker" and get an avalanche. You've read enough to know better — the skill is in the asking:

You: We're building a tiny issue-tracker CLI in Python. Create the repo skeleton: git init, a README saying what this is, and an empty tracker.py. Don't write features yet.

Claude works. And then — the first surprise of the day — it asks: a permission prompt, wanting to run git init. You press Yes. It asks again for the file writes. Yes. Yes. On your first session it asks before each change; you approve with your eyes open, watching exactly what it touches.

The mode dial

Mid-morning, you try the one hotkey worth memorizing: Shift+Tab. A little indicator cycles — manual, plan, auto. You learn what the modes mean by feeling them:

  • Manual: Claude asks before acting. Slow, safe — for the risky parts.
  • Plan: Claude explores read-only and brings you a plan. You approve the thinking before any editing happens.
  • Auto: a classifier reviews actions instead of you. For the boring stretch.

Beginners drift — rubber-stamping everything, or drowning in prompts. You decide, right there, to choose the mode on purpose, every session.

Afternoon: the skeleton gets bones

You: Good. Now add a minimal add command: python tracker.py add "text" appends the task to a JSON file with an auto-incrementing id, then prints the id. Keep it under 30 lines.

Small asks. Pointed asks. One behavior at a time — and each time, you read the diff before approving. By 4 p.m. you have: a repo, a README, a working add, and a first commit you actually understand, because you watched every line land.

Marco the intern leans over. "Is that the AI thing? Does it just… do your job?"

"No," you say, and mean it. "It does the typing. The job is still mine."

What Chapter 1 taught (through the story) Install and auth; the interactive loop; permission prompts as a feature; the three modes and the discipline of choosing; and the habit that separates operators from tourists — small, pointed asks, and read every diff.

Your turn — the chapter's hands-on

Do it in your real repo
  1. Install Claude Code; verify claude --version; authenticate.
  2. mkdir tracker && cd tracker && claude
  3. Ask for the skeleton (repo, README, empty tracker.py) — approve each action, reading each one.
  4. Shift+Tab through all three modes deliberately.
  5. Ask for the add command as one small pointed request. Read the diff. Approve.
  6. python tracker.py add "survive week one" — see id 1 come back.
  7. Commit (ask Claude for a good message).

Checkpoint (your save file): a git repo with README + tracker.py + a working add, one commit, and you can name the three modes without looking. Report this to your agent — the story continues from Chapter 2: The Thursday demo.
