Lesson 0020 · Phase 5 — Professional depth (CCAR-P)

Lifecycle management: handoff, observe, iterate

"The last mile often becomes most of the journey." — Anthropic, on shipping agents

≈ 14 minutes Exam: CCAR-P · Stakeholder Comm. & Lifecycle · 14% Completes the lifecycle domain
Three planes of observation: business, behavioral, consumption — each catches what the others miss.

0019 ended discovery with six artifacts. The lifecycle's back half — handoff → monitoring → iteration — is where solutions live or die, and Anthropic's own production post is blunt: the gap between prototype and production "is often wider than anticipated," because in agentic systems "minor changes cascade into large behavioral changes." Today you learn to run what you shipped.

Handoff: transferring the mental model

The anti-pattern is the departing architect taking the design's reasoning with them. The fix: artifacts carry the mental model. A complete handoff package:

  • The discovery set (0019) — criteria, constraints, posture, and the recorded reasons losing options lost: future maintainers inherit the why.
  • The runbook — 0018's degradation ladder is the incident playbook: each failure mode with its designed exit, its owner, and its escalation path. Uncertain-state procedures (0007) spelled out: verify-don't-retry, with the idempotency key's role documented.
  • The eval suite (0016) — ops can rerun it; changes become safe to make because they're gated by something.
  • The policy map — who may change what: permission rules, managed settings, hook allowlists (0009/0010's trust model, applied to humans).
  • Session/resume mechanics — where checkpoints live, how resume works (0012's sessions; 0015's durable execution), so long-runners survive redeploys.

One consumption tell worth training on: the cache-invalidation event is visible in the usage curve. Tuesday's tool redeploy (0017's hierarchy: tools → system → messages) shows up as a spike of uncached input — the write premium plus full-price reads — exactly when you shipped. If you can read that spike, you can price your release schedule.

Iterate: the change discipline

  1. Changes cascade. "Small changes to the lead agent can unpredictably change how subagents behave" — emergent behavior means every prompt edit is a system edit.
  2. Evals gate the change. 0016's loop is the iteration protocol: refine → test on the suite → held-out final validation → ship. Without it, you're hot-fixing prose into a running production system.
  3. Deploy compatibly. Long-running, stateful agents mid-task can't all be swapped at once — rainbow deployments shift traffic gradually while old and new run side by side.
  4. Protect the runners. Checkpoints and resume, never restart-from-zero; and when a tool fails in flight, tell the agent — adaptation "works surprisingly well."
  5. Close the loop to discovery. When the business shifts, criteria shift — the lifecycle is a circle, and 0019's artifacts get revised, not archived.

Exercise — the hospital handoff package (exam-style)

You're rotating off the 0019 intake assistant. Produce: (1) three runbook entries (one per failure mode: EHR read outage, mid-write timeout, model overload); (2) the three-plane dashboard — name the metric per plane and its alert threshold shape; (3) the change process when a nurse requests softer symptom-question phrasing; (4) what next Tuesday's tool-redeploy looks like in the usage curve, and what you tell finance.

Check your answer

(1) EHR read outage → degradation ladder: say so, structured fallback questions, nurse queue; owner: on-call ops; escalation: hospital systems team. Mid-write timeout → verify via idempotency key before any retry; never blind-retry a write; owner: app on-call. Model overload → queue with streamed notice, static FAQ floor; never silence.

(2) Business: deflection paired with CSAT (alert on divergence — deflection up while CSAT falls = gaming). Behavioral: escalation accuracy ≥95%, tracing of routing decisions (PHI lane hit rate 100% — a compliance alarm, not just quality). Consumption: uncached-input ratio and daily spend by workspace/model; alert on step-changes.

(3) Not a hot edit: capture the request → update the script/prompt → eval suite run (the nurse-facing criteria from discovery) → held-out validation → rainbow deploy → watch escalation accuracy for a regression — emergent behavior means "just phrasing" is a system change.

(4) A spike of uncached input at deploy time: cache writes at 1.25× plus full-price reads until the new prefix settles (tools sit atop the invalidation hierarchy). Tell finance: it's a predictable, one-time-per-release cost — and the argument for batching tool changes rather than trickling them. If your answer included "usage report by API key shows exactly which service ate the premium," you're reading production data like an architect.
