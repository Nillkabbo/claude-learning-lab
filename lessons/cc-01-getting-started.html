CC-01 · Phase A — The first week

Getting started: install, first session, the permission dance

From zero to your first agent-assisted change — on your machine, today.

≈ 15 minutes + the drill Source: official quickstart Hands-on required
your first session

Welcome to the Claude Code track. This lesson is deliberately practical: by the end of the drill you'll have installed Claude Code, run your first session, approved your first file change, and learned the one habit that separates beginners from operators (Shift+Tab).

Install (native, not npm)

# macOS / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

# or Homebrew (stable channel)
brew install --cask claude-code

Verify with claude --version. Native installs auto-update; Homebrew/WinGet need manual upgrades. On Windows, install Git for Windows so the Bash tool works properly (it falls back to PowerShell otherwise).

First run: authentication

Run claude inside a project directory. First use prompts a browser login. What you can authenticate with — know the menu:

  • Claude Pro/Max/Team/Enterprise subscription (recommended — usage included in the plan)
  • Console credits (pay-as-you-go; a "Claude Code" workspace is auto-created for cost tracking)
  • Bedrock / Vertex / Foundry (enterprise clouds)
  • A corporate gateway with SSO

If ANTHROPIC_API_KEY is set, login is skipped in favor of the key. /login switches accounts later; credentials persist.

The interactive loop and the permission dance

Type natural language; Claude reads files and proposes changes. Your first session asks before each change — approve with Yes and watch what it does. After that, on Pro/Max/Team, sessions start in auto mode: a classifier reviews actions instead of you. Other plans start in Manual.

The habit that matters: Shift+Tab Press Shift+Tab anytime to cycle permission modes. Beginner sessions drift into either rubber-stamping everything or drowning in prompts — cycling modes deliberately (manual for risky areas, plan for exploration, auto for the boring stretch) is the operator's move. This extends 0009's mode table with the muscle memory.

Your first commands (the quickstart's own list)

"what does this project do?"          # understanding
"explain the folder structure"
"add a hello world function to the main file"   # your first change
"what files have I changed?"
"commit my changes with a descriptive message"  # git, through Claude

/help    /clear    /exit        # session commands (Ctrl+D twice also exits)
claude -p "explain this function"   # one-shot, non-interactive
claude -c                           # continue the most recent session
claude -r                           # resume a listed session
The win Claude Code installed and verified, authenticated with the right account type, one real change approved with eyes open, modes cycled on purpose, and the -p / -c / -r trio in your fingers. You are no longer a beginner at the door — you've walked through it.

Your turn — the day-one drill (on your machine)

Exercise — first contact

Pick any small real project (or mkdir ~/cc-first && cd ~/cc-first with a couple of files). Then:

  1. Install, verify claude --version, authenticate.
  2. Ask "what does this project do?" — read the answer critically.
  3. Ask for one small change; approve it in manual; inspect the diff.
  4. Shift+Tab into plan mode; ask for a bigger change; read the plan before any edit.
  5. Exit; then claude -c to continue and claude -p "summarize what we did" to go one-shot.

Report to your agent: which mode felt right for step 3 vs step 4, and one thing Claude did that surprised you. That report is the drill's answer key — it calibrates every CC lesson after this.
