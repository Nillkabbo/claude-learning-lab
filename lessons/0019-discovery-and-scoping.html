What discovery must produce

Discovery isn't meetings — it's artifacts. Done well, it hands design a complete input set, and every item is something this course already taught you to build:

The stakeholder map — who owns what

  • Business owner — value framing: deflection, CSAT, handle time, the 15×-token question ("is this task valuable enough for an agent?").
  • Domain experts — the official pattern: "work with your support team to define success criteria" and script ideal interactions. They own the definition of right; you own making it measurable.
  • Security & compliance — which layers are enforced (PII stripping, regulated-data routing, gates). Discovery output: the list of rules that must live in code, not prompts.
  • Engineering/ops — who inherits handoff and monitoring (0020's stakeholders); they set the deployability constraints (rainbow deploys, checkpoints).
  • Finance — the lever map (0017) is your conversation artifact: batch 50%, cache reads 0.1×, effort dials, per-tier routing.

The architect's job in one sentence: translate each stakeholder's requirement into an artifact from an earlier lesson — so nothing stays a vibe.

The structured method

  1. Script ideal interactions with the experts — the official first step before any building. Tasks fall out (greeting, lookup, action, escalation).
  2. Criteria before prompts — specific, measurable, achievable, relevant; numeric thresholds anchored to benchmarks. "This cycle is central" applies to projects, not just prompts.
  3. Walk the failure catalog in advance — what happens when the EHR integration dies mid-write? Who gets paged? What does the customer see? Stakeholders define failure costs; you design the degradation ladder to match.
  4. Scope to the simplest solution — the 0013 ladder as a communication tool: "here's what one more rung of complexity buys, and here's the latency/cost/risk bill." Scope creep becomes arithmetic instead of argument.
  5. Decide the posture — run the product chooser against the constraints; record why the losing options lost. That record is your defense in design review.

Communicating decisions

CCAR-P explicitly tests "communicating architectural decisions." The formats that work:

  • Trade-off tables — capability × latency × cost per option, with the verified numbers doing the persuading.
  • The one-page design doc — every requirement → its artifact → its owner. If a requirement has no artifact, it's not yet a requirement; if an artifact has no owner, it's a risk.

The win You can run a discovery engagement that ends with six artifacts instead of a slide of adjectives: numeric criteria, the constraint inventory, a ladder-scoped capability, a justified product posture, a failure catalog with costs, and expert-written scripts — each traceable to an owner. That is the CCAR-P discovery subdomain, operationalized.

Your turn

Exercise — run the hospital discovery (exam-style)

A hospital wants an intake assistant: PHI everywhere, nurses as domain experts, an existing EHR integration (real-time reads, gated writes), 30s-max first response, and a CFO who's seen the token bill of a previous AI project.

On paper: (1) produce all six discovery deliverables (compact form); (2) the stakeholder-owner matrix; (3) one trade-off table for the "how much agent" decision; (4) name what 0014's routing and 0018's compliance stack each absorb.

Check your answer

(1) Criteria: e.g. intake-field accuracy 100% (medical!), nurse-approval escalation accuracy ≥95%, first-token p95 < 2s, PHI leakage 0. Constraints: PHI (regulated routing + certified models + PII stripping), 30s budget (tiered models + streaming), EHR (client tools w/ confirmation gates; idempotency on writes). Capability: workflow first — routing + chained retrieval, an agent loop only for the free-text symptom intake if criteria demand it. Posture: Agent SDK embedded in the intake app (or Managed Agents if the hospital refuses to run anything) — recorded reasons. Failure catalog: EHR down → structured fallback + nurse queue, never invented data; mid-write timeout → verify-don't-retry. Scripts: written with nurses, per task.

(2) Business/CFO → criteria + lever map; nurses → scripts + eval labels; security → enforced-rules list (PII/routing/gates); ops → handoff + deployability; you → the artifact set itself.

(3) Rows: single retrieval call / routed workflow / intake agent. Columns: accuracy ceiling, PHI exposure surface, latency, token cost (single ≪ workflow ≪ agent; multi-agent 15× noted as out of scope), failure blast radius. Recommendation marked, losing options' reasons recorded.

(4) Routing absorbs: PHI-only lane to certified models, easy/ hard tiering. Compliance stack absorbs: deterministic PII stripping, gates + idempotency on EHR writes, harmlessness screens on intake text. If your matrix shows security owning the enforced rows while nurses own the criteria — you've got the translation job right.
