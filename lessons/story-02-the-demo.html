The Thursday demo

In which the demo goes well, a quote character ruins Friday, and plan mode saves you from yourself.

≈ 10 minutes + hands-on Concepts: plan mode · reading diffs · iterating · checkpointing Project gains: a fixed bug, a list command, v0.1 tagged

Thursday, 2:00 p.m.

The demo works. Priya adds three tasks live, watches the ids increment, and says "acceptable," which you will learn is her highest praise before "good." She wants list by Monday. Marco claps, once, for the ids.

Friday, 10:15 a.m. — the bug

You're adding list yourself when Marco shouts across the desk: "It breaks on quotes!"

$ python tracker.py add fix the "login" bug
… json.decoder.JSONDecodeError … tasks.json is now empty

Two bugs in one: the shell ate the quotes into separate arguments, and — far worse — a failed write wiped the tasks file. Your data survived because you backed up before the demo. Priya appears behind you, reading the traceback over your shoulder.

"So fix it. Use plan mode — this touches file writes."

Plan first, then hands

Shift+Tab into plan. Claude explores read-only — reads tracker.py, checks the JSON handling — and returns a plan instead of an edit:

Plan: (1) join argv fragments so multi-word tasks stay one task; (2) make writes atomic — write to a temp file, move into place — so a failed write can never truncate the real file; (3) add list: print id + status + text.

And here is the moment the chapter is secretly about: you read the plan and catch a problem. "Number two — also validate before replacing. If the existing JSON is corrupt, don't destroy it; back it up as tasks.corrupt.json first." Claude amends the plan. That is plan mode's whole value: you corrected the thinking for free, before a single line was edited.

You approve. Diffs appear — small, readable, one concern each. You read them, actually read them, because Monday's Priya question will be "what did you change and why," and "the AI did it" is not an answer.

The save file saves you

Then Claude's second edit accidentally renames the wrong function. Before you can swear, you remember — checkpoints. You rewind the session's file changes, re-ask with the plan amended, and the fixed edit lands clean. The whole detour costs ninety seconds.

What just happened, named Plan mode = decisions before mutations. Reading diffs = your name on every change. Checkpointing = iterate boldly, recover cheaply. Together they are the difference between "an AI did stuff in my repo" and "I ship with confidence."

Monday, 9:30 a.m. — v0.1

list works. Quotes are just characters again. The atomic-write fix survives Marco's best attempts to break it (he tries; he's an intern, it's his job). You tag it:

git tag -a v0.1 -m "add + list, atomic writes"
git push --tags

Priya looks at the log — small commits, each one explainable — and says "good." Recorded: the first "good."

What Chapter 2 taught Plan mode as the pre-edit contract (and amending the plan as the real skill); atomic writes — an error-handling lesson wearing a story's clothes; reading diffs as authorship; checkpointing as your undo.

Your turn — the chapter's hands-on

Do it in your real repo
  1. Reproduce the quote bug: python tracker.py add fix the "login" bug — watch it fail (safely, this time).
  2. Shift+Tab to plan; ask for the fix plus atomic writes plus list; read the plan; amend it once on purpose.
  3. Approve; read every diff; if anything lands wrong, rewind via checkpoint and re-ask.
  4. Verify: add a quoted task, list tasks, hand-break tasks.json and confirm the corrupt-backup behavior.
  5. Commit small; tag v0.1.

Checkpoint: add + list working, atomic writes proven by a deliberate corruption test, v0.1 tagged. Report it — next week, in Chapter 3, Marco keeps asking the same questions, and you discover why CLAUDE.md exists.
