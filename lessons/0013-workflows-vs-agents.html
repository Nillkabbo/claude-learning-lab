Lesson 0013 · Phase 4 — Agentic architecture · 27%

Workflows vs agents: when not to build an agent loop

The most important architecture decision is the complexity you decline.

≈ 15 minutes Exam: Agentic Architecture · 27% The heavyweight domain begins

Phase 4 opens with the essay that named this territory — Anthropic's "Building effective agents". One note before anything else: the post now carries a banner saying the tooling landscape has changed since December 2024 (see Managed Agents for the current stack) — but its architectural vocabulary is exactly what the 27% domain tests. Today: the decision that everything else in this phase hangs on.

Two definitions, quoted exactly

"Workflows are systems where LLMs and tools are orchestrated through predefined code paths."

"Agents, on the other hand, are systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks."

Both are agentic systems — Anthropic's umbrella term. The dividing line is one question: who owns the control flow? Your code (workflow) or the model (agent)? Everything you've built since 0005 was the raw material; this is the architectural act of deciding who assembles it.

Lesson 0013 — the complexity ladder: each rung buys flexibility and bills latency, cost, and risk.

The decision, in the essay's own words

  • Start at the bottom: "find the simplest solution possible, and only increase complexity when needed. This might mean not building agentic systems at all." For many applications, "optimizing single LLM calls with retrieval and in-context examples is usually enough."
  • Workflows "offer predictability and consistency for well-defined tasks" — you can name the steps in advance.
  • Agents are "the better option when flexibility and model-driven decision-making are needed at scale" — open-ended problems "where it's difficult or impossible to predict the required number of steps."
  • The universal trade: agentic systems "trade latency and cost for better task performance." If nobody can state what the extra performance buys, the complexity is unfinanced.

When agents earn their keep

Agents stay in control by getting "ground truth" from the environment at each step — tool call results, code execution — to assess progress, pausing for human feedback at checkpoints, and terminating on completion or a stopping condition (a maximum iteration cap — the same discipline as 0007's error budgets and 0011's maxTurns). The essay is equally clear about the price: "higher costs, and the potential for compounding errors," bought down with "extensive testing in sandboxed environments, along with the appropriate guardrails" — your Phase 2–3 toolkit, mandatory now.

Two flagship domains where agents genuinely win (both from Anthropic's own work): customer support — conversation plus action, tools for refunds and data, "success clearly measured through user-defined resolutions" — and coding agents — verifiable via tests, iterable on test feedback. Common thread: clear success criteria and a feedback loop.

The five patterns, previewed

PatternShapeUse when
Prompt chainingSequential calls, programmatic gates betweenTask cleanly decomposes into fixed subtasks; trading latency for accuracy
RoutingClassify, then dispatch to specialized handlersDistinct input categories; enables per-tier models (Haiku for easy, Sonnet for hard)
ParallelizationSectioning (independent subtasks) or voting (multiple attempts)Speed, or multiple perspectives for confidence (guardrails, vulnerability voting)
Orchestrator-workersCentral LLM decomposes, delegates, synthesizesSubtasks can't be predicted in advance (multi-file code changes)
Evaluator-optimizerGenerate ↔ critique loopClear evaluation criteria; refinement demonstrably helps

"These building blocks aren't prescriptive" — combine and customize them, and add complexity "only when it demonstrably improves outcomes." Lesson 0014 takes chaining, routing, and their siblings apart in depth; 0015 does orchestrator-workers.

ACI — the principle you already met The essay's third principle: craft the agent-computer interface with the same effort you'd give a human-computer interface. Its best story is poka-yoke — the SWE-bench agent misused relative paths, so the tool was changed to require absolute paths, and "the model used this method flawlessly." That's 0006's tool design and 0004's constrained decoding, philosophy unified: make the right thing the only easy thing.
The win You can now make the call every scenario question in the 27% domain starts with — single call, workflow, or agent — and defend it in the essay's own terms: who owns control flow, what the latency/cost trade buys, where the ground truth comes from, and what the stopping condition is.

Exercise — classify six builds (exam-style)

For each, pick single call / workflow (name the pattern) / agent — one sentence of justification each:

  1. Extract invoice totals from PDFs into JSON.
  2. Generate marketing copy, then translate it into German.
  3. Sort support tickets into billing / technical / general, easy ones to a cheaper model.
  4. Resolve GitHub issues that may touch dozens of files, verified by tests.
  5. Polish literary translations using a critic that suggests refinements.
  6. Screen code for vulnerabilities using several independent prompts that must agree.
Check your answer
  1. Single call + structured outputs (0004). No steps to orchestrate.
  2. Workflow: prompt chaining — fixed subtasks, a gate can check the copy before translation.
  3. Workflow: routing — classification then specialized handlers; the essay's own Haiku/Sonnet example.
  4. Agent — "difficult or impossible to predict the required number of steps"; tests provide ground truth per step; cap iterations.
  5. Workflow: evaluator-optimizer — clear criteria, refinement demonstrably helps.
  6. Workflow: parallelization (voting) — multiple perspectives, threshold to balance false positives/negatives. If you called 4 or 6 an agent, reread the ladder: no model-owned control flow, no agent.

Six for six with the control-flow argument? You're answering the 27% domain's opening question the way it's graded.
