Workflow design: escalation, compliance, degradation, handoff

The customer-service scenario — and the whole course assembled into one product.

≈ 16 minutes Exam: customer service workflow design Everything from 0001–0017 applies
The support flow: route by lane, gate the draft, vote on safety, escalate with context — every failure has a designed exit.

The exam guide names this area precisely: escalation, compliance enforcement, graceful degradation, handoff design. It's the capstone of the 27% domain because every lesson converges here — the tool loop (0005), confirmation gates (0006), uncertain state (0007), context budgets (0008), permission thinking (0009), routing and voting (0014), agent judgment (0013), evaluation (0016), cost (0017). Today they become one workflow, grounded in Anthropic's official customer-support guide.

Design before building

The official first step isn't a model call — it's a script: write the ideal interaction, break it into discrete tasks (greeting, product info, conversation management, quote/order actions), and draw the flowchart before building. Then:

  • Prompt structure, per the guide: keep only role and identity in the system prompt — "Claude actually works best with the bulk of its prompt content written inside the first user turn." (A deliberate contrast with your instinct from 0002 — scope and task content ride in user turns; policy still belongs above.)
  • Model per tier: Opus-class to "balance intelligence, latency, and cost"; Haiku-class for latency-sensitive multi-step flows. Stream responses — visible progress buys patience, which can justify the better model.
  • Retrieval vs tools: RAG for large static knowledge ("can improve performance and efficiency"); tools when answers need real-time data — embedding retrieval "is not sufficient" there.
  • Routing last: a separate intent classifier routing to specialized conversations works at scale, but adds a latency-paying call — "exhaust prompt engineering and added tools first."

Escalation: a measurable capability

The guide's reframe: escalation isn't failure, it's a skill with a target — "escalation accuracy of 95% or higher", the ability "to recognize when a query needs human intervention and escalate appropriately." Triggers you already own: low confidence (0004's human-review layer), policy-mandated topics, high stakes (0006's confirmation gate), or the customer asking.

Handoff design is context transfer: the human receives the conversation summary, the state (account, actions taken, 0008's summary discipline), and provenance — 0015's filesystem-artifact pattern is exactly the anti-telephone handoff. The business balance: deflection of 70–80% (inquiries resolved without humans) against CSAT ≥ 4/5 — over-escalation wastes money, under-escalation burns customers, and only paired metrics keep you honest.

The compliance lesson is 0009's inversion: prompts are "context, not enforced configuration" — so compliance lives in the layers that are enforced: filters, gates, routes, and the evals (0016) that watch them. The guide's own targets: comprehension ≥95%, relevance ≥90%, informational accuracy 100%, citations in 80% of relevant interactions, topic adherence ≥95%.

Graceful degradation: the ladder

  failure                    degraded mode                     never
  ─────────────────────────  ────────────────────────────────  ─────────────
  refunds tool down          polite decline + alternatives     fabrication
  search index stale         say so, offer cached answers      confident lies
  tool times out mid-charge  verify outcome before retry       double charge
  model overload             queue, stream notice, retry       silence
  whole agent stack down     static FAQ + human queue          dead air

Notice the scope rules are degradation design: "politely decline unavailable ones" is the refunds-tool-down behavior, decided in advance. The principles you've earned: instructive errors the model can adapt to ("works surprisingly well" — 0015), verify-don't-retry on uncertain state (0007), checkpoints and resume (0015), and RAG fallbacks for static knowledge. The cardinal rule: the failure mode must never be silence or fabrication — every break has a designed exit.

Exercise — design Apex Support end-to-end (the capstone)

Apex Airlines' support agent handles: flight status (real-time), rebooking (irreversible), compensation claims (regulated), and general questions (static FAQ). Design:

On paper: (1) the task script and which capability serves each task (RAG / tool / routed tier); (2) the escalation triggers and what the human receives; (3) the compliance stack, naming the enforcement layer for each rule; (4) the degradation ladder for: status API down, claim tool mid-charge timeout, model overload; (5) four paired metrics with numbers.

Check your answer

(1) Status → client tool (real-time; RAG insufficient). Rebooking → tool behind a confirmation gate. Claims → routed to the certified/regulated tier (0014's privacy routing). FAQ → RAG over static knowledge. Tiered models: Haiku for simple flows, Opus-class where judgment pays; stream everywhere.

(2) Escalate on: low confidence, regulated edge cases, customer request, failed compensation policy match. The human receives: conversation summary, account + actions-taken state, and the claim artifacts (filesystem references — no telephone game), targeting ≥95% escalation accuracy.

(3) Scope rules in prompts (context); citations + fact-checking (grounding + cross-model judges); harmlessness screens; deterministic filters — PII stripping, competitor filter; confirmation gates + idempotency keys on rebooking/compensation; privacy route as enforcement. Each rule has a named enforced layer — prompts alone enforce nothing.

(4) Status down → say so, offer rebooking alternatives and the static schedule, never invent a status. Mid-charge timeout → verify-before-retry with the idempotency key, escalate with state if unverifiable. Model overload → queue with streamed notice, FAQ fallback + human queue as the floor. No silence, no fabrication, anywhere.

(5) e.g. deflection 70–80% paired with CSAT ≥ 4/5; escalation accuracy ≥95%; informational accuracy 100% with citations in 80% of relevant interactions; p95 first-token latency fit to tier. If you paired every efficiency metric with an experience metric — you've internalized why single-number targets produce bad agents.
