Chapter 6 of 12 — the story so far.

The request from above

Meridian's actual issue tracker is GitHub — Tracker is becoming the team's local scratchpad, and Priya wants one bridge: "When I say sync, pull the open issues assigned to me into Tracker. Don't make it a project."

Claude can't read GitHub. Not yet. The protocol that changes that is MCP — Model Context Protocol: servers that expose tools (actions), resources (data), and prompts (templates) to your session. You add the GitHub MCP server, and its tools join yours.

The consent moment

And here the story slows down, because something important happens: connecting a server, Claude Code shows you what it will run — the exact command, untruncated — and asks permission. Not a formality. A local MCP server is code running with your privileges; the consent screen is the moment you decide what you're inviting in.

You do in ten minutes what sloppy teams skip forever — a trust review, straight from your future certification's security chapter:

  • Tokens: the server holds its own GitHub token. Never yours passed through. (Token passthrough is a forbidden anti-pattern for exactly the audit reasons you can now feel.)
  • Scopes: read-only on issues. When it later asks for write access, that's a separate, explicit elevation — minimal first, escalate deliberately.
  • Surface: you note what its tools can touch, in writing, in the repo's CLAUDE.md. Reviewers after you will want that note.

The bridge

With the server connected, the sync itself is almost an anticlimax — a skill, because the procedure deserves the same treatment as releases:

---
description: Pulls my open GitHub issues into Tracker as tasks. Use when asked to sync.
allowed-tools: mcp__github__list_issues, Read, Write
---
Fetch open issues assigned to me. For each: if no Tracker task mentions the issue
number, add one formatted "[gh-42] title". Report added and skipped counts.

/sync. Eleven issues arrive as tasks, each tagged with its source — provenance, so a task always traces back to where it was born. Priya runs it once, nods, and says the thing she says instead of thank you: "Ship it to the others."

What just happened, named MCP extends your session with external capabilities under a trust model: consent at the boundary, least-privilege scopes, no token passthrough, and — the habit that outlives this chapter — writing the review down.

Your turn — the chapter's hands-on

Do it in your real repo
  1. Connect one real MCP server (GitHub if you have a token, or any server you actually need). Read the consent screen like you mean it.
  2. Run the ten-minute trust review: tokens / scopes / surface — write three lines into your CLAUDE.md.
  3. Run /context and note the token cost of the server's tool definitions. Is each tool earning it?
  4. If GitHub: build the /sync skill and run it. If not: build one small skill against your server's most useful tool.
