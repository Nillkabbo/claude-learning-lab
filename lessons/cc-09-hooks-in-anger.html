CC-09 · Phase C — Power user

Hooks in anger: lifecycle automation that fails safe

React to the lifecycle — and know exactly what hooks must never be trusted with.

≈ 12 minutes + drill Claude Code Guide Hands-on by design
exit 2 blocks

0010's verified contract, operationalized. Three cadences (session / turn / tool call); config nests event → matcher → handlers; handlers can be command, http, mcp_tool, or prompt.

  • Exit 0: stdout as JSON decisions — permissionDecision, additionalContext, systemMessage; plain text on UserPromptSubmit/SessionStart becomes context.
  • Exit 2 blocks — regardless of any JSON "allow". A Stop hook exiting 2 prevents stopping.
  • Hard rules still belong to permissions: hook if matching fails open, and a mistyped path silently disables the gate. Hooks shine at context injection, formatting, notifications, audit.
  • Lists merge across settings scopes; repo hooks need workspace trust; allowManagedHooksOnly exists for orgs.

Exercise
