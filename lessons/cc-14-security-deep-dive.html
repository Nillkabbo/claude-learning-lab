Security deep-dive: sandboxing and data

What runs where, what leaves, and which walls are real.

≈ 12 minutes + drill Claude Code Guide Hands-on by design
sandbox + ZDR

Track 1's enforcement layers, plus Claude Code's own walls:

  • Sandboxed Bash — the sandboxed Bash tool runs commands in a restricted environment; sandbox substitution can stand in for whole-tool Bash asks (autoAllowBashIfSandboxed), while explicit denies and dangerous paths still apply. Choose a sandbox environment per platform (official pages).
  • Permissions are the guarantee layer — deny→ask→allow, first match; a bare-tool deny hides the tool entirely.
  • Data boundaries — the official Security and Data Usage pages: what's sent, retention, and zero data retention for orgs that need it. MCP servers stay untrusted (0021): consent, progressive scopes, no passthrough.

The audit posture from 0018/0021 transfers directly: list every boundary, name the enforced layer behind it, and test that a broken gate fails loud.
