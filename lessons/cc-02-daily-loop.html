CC-02 · Phase A — The first week

The daily loop: sessions, /commands, workflows

From first contact to daily driver — the habits that make sessions cheap and context clean.

≈ 12 minutes + drill Claude Code Guide Hands-on by design
sessions: /clear · -c · -r

Three session tools prevent 90% of beginner mess:

  • /clear — start fresh when the task changes. Old context bills tokens and rots focus (Track 1's Law 7 applies per session).
  • claude -c — continue the most recent session; claude -r — resume from a list. Context you already paid for is worth resuming; a new task is worth /clear.
  • /status and /context — inspect what loaded: settings sources, memory files, token usage. Operators look before they steer.

The built-in /commands run fixed logic (/help, /compact, /memory, /permissions, /init…); bundled skills like /code-review and /debug orchestrate tools instead. Checkpointing lets you rewind file changes when a session went wrong. The common workflows doc is the official pattern book — explore first, then change, then verify.

Exercise

In a real project: run /context and note the biggest context item; /clear; ask one small task; exit; claude -c and confirm the history survived; then claude -p "what did we just do?". Report which of the three resume-vs-clear calls felt right and why.
