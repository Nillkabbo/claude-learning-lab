Lesson 0010 · Phase 3 — Claude Code & the Agent SDK

Claude Code in the team: hooks, slash commands & shared config

One product, many machines, an org policy — how configuration travels, and who wins.

≈ 15 minutes Exam: Claude Code Configuration · 20% No install needed
Hooks fire at three cadences — session, turn, tool call — and the exit-2 contract is the same at each.

Lesson 0009 gave you the three pillars solo. Teams add the interesting problems: config that travels through a repo, policy that comes from the org, behavior that must fire every time, and procedures every teammate can invoke. That's hooks and slash commands — plus a sharper rule than 0009's about which layer guarantees.

Hooks: the policy engine

Hooks are "user-defined shell commands, HTTP endpoints, or LLM prompts that execute automatically at specific points in Claude Code's lifecycle." They run at three cadences:

CadenceEvents you'll actually use
Per tool callPreToolUse (can block), PostToolUse, PermissionRequest, PermissionDenied
Per turnUserPromptSubmit, Stop, PreCompact
Per sessionSessionStart, SessionEnd

Configuration nests three deep — event → matcher group → handlers — and handlers can be command, http, mcp_tool, or prompt:

{ "hooks": { "PreToolUse": [
    { "matcher": "Bash",
      "hooks": [ { "type": "command",
                   "if": "Bash(rm *)",
                   "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh" } ] }
] } }

The exit-code contract is the heart of it:

  • Exit 0 — success. Stdout beginning with { is parsed as a JSON decision (permissionDecision: "deny"/"allow", additionalContext, updatedInput, systemMessage); on UserPromptSubmit/SessionStart, plain-text stdout becomes context Claude reads.
  • Exit 2 — blocking error, regardless of JSON: "even a JSON allow can't override it." PreToolUse blocks the call, UserPromptSubmit rejects the prompt, and — the clever one — Stop prevents stopping, forcing Claude to continue.
  • Timeouts render no decision — "don't count on a stalled hook to act as a gate."
The refinement 0009 earned — and the exam tests Yes, exit 2 blocks before rules run. But hooks are the wrong tool for hard allow/deny: if matching is best-effort and fails open, and a mistyped script path in settings.json "leaves the gate silently disabled." Official guidance: use the permission system for hard enforcement; use hooks for what hooks are good at — injecting context, post-formatting, notifications, audit logs. Defense in depth, with the guarantee in the rules layer.

Team mechanics: hook entries merge across settings levels; repo-file hooks require workspace trust (same asymmetry as allow rules); cloud sessions ignore your local ~/.claude/settings.json entirely; and enterprises can set allowManagedHooksOnly or disableAllHooks (which can't touch managed hooks from outside managed settings).

Slash commands: procedures that travel

The big recent change: "custom commands have been merged into skills." A file at .claude/commands/deploy.md and a skill at .claude/skills/deploy/SKILL.md both create /deploy and work the same way — but skills are recommended, since they support extra files, invocation control, and relevance-based auto-loading.

  • Locations: project (committed, shared), personal (~/.claude/), enterprise (managed), or plugins — with precedence enterprise > personal > project, and a skill winning over a same-named command.
  • Arguments: $ARGUMENTS (all args), $1, $ARGUMENTS[0]; stacking works — /write-tests /fix-issue 123 loads both. If you don't reference $ARGUMENTS, it's appended automatically.
  • Frontmatter that matters: allowed-tools — a per-turn tool grant that clears when you send your next message; context: fork — run in a forked subagent context (fresh context, results returned — pure subagent pattern, previewing 0011); disable-model-invocation: true — humans-only; model, argument-hint, hooks.
  THE TEAM ARTIFACT MAP — what lives where

  concern                    artifact                     file
  ─────────────────────────  ──────────────────────────  ───────────────────────────
  standing guidance          CLAUDE.md                    ./CLAUDE.md (shared)
  hard guarantees            permission rules             managed / .claude/settings.json

  repeatable procedures      commands / skills            .claude/skills//SKILL.md
  one dev's preferences      local overrides              CLAUDE.local.md, settings.local.json
The win You can now equip a whole team: hooks that add context and audit without pretending to be firewalls, slash commands that encode procedures with correct frontmatter (allowed-tools grants, context: fork isolation), and the artifact map that answers "where does this concern go?" in one look.

Your turn

Exercise — wire the quality gate

The Apex tooling team wants four things: (a) every Bash call logged to an audit file; (b) every user prompt silently preceded by "Check CONTRIBUTING.md before proposing file moves"; (c) a /review-pr procedure any teammate can run that works in an isolated fresh context with read-only tools; (d) a guarantee that rm -rf never runs.

On paper: for each, name the artifact type, the file it lives in, and sketch the config — including the exit codes for (a)'s logger and the frontmatter for (c).

Check your answer

(a) PostToolUse hook, matcher Bash, type command, appending to the audit log — and it should exit 0 (a logger must never block; PostToolUse can't un-run the tool anyway). Shared .claude/settings.json.

(b) UserPromptSubmit hook printing the reminder as plain text (exit 0, stdout becomes context Claude reads) — or JSON with additionalContext. Exactly what hooks are for: context, not enforcement.

(c) A skill: .claude/skills/review-pr/SKILL.md with frontmatter allowed-tools: Read, Grep, Glob (per-turn grant), context: fork (fresh subagent context — long PR reviews don't pollute the main session), optionally disable-model-invocation: true so only humans trigger it.

(d) Not a hook — hooks fail open. A deny rule (Bash(rm -rf *)) in managed or shared settings is the guarantee; belt and suspenders adds a PreToolUse blocker, but the rule is the load-bearing wall. If all four match the artifact map without hesitating, this domain is yours.
