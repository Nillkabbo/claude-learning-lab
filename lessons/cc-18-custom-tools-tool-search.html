Custom tools & tool search at scale

Give the engine your own hands — and keep the tool bill sane when tools multiply.

≈ 12 minutes + drill Claude Code Guide Hands-on by design

Custom tools in the SDK (official page): your functions join the loop with the same interface discipline you already own — names, four-question descriptions, schemas, strict: true. Law 5 hasn't changed; you're just the author now.

Tool search (official SDK page): when definitions outnumber sense, the tool-search tool defers them — loading definitions on demand instead of up front. Why it matters, from Track 1's economics:

  • Every shipped tool definition bills tokens every request (~264–804 overhead) whether used or not.
  • Big static registries also invite selection ambiguity — fewer, well-described tools beat many vague ones (0006's consolidation).
  • Namespacing matters especially under tool search (official define-tools guidance).

The design ladder: consolidate → describe properly → only then defer via tool search.
