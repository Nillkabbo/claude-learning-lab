Orchestrator-workers & multi-agent design

The fifth pattern — plus the production numbers Anthropic published about running it.

The pattern

A central LLM dynamically decomposes the task, delegates subtasks to specialized workers, and synthesizes their results. Unlike chaining or routing, the steps aren't predefined — that flexibility is the point (the essay's example: code changes needing "coordinated changes across many files"). "The essence of search is compression": each subagent explores its own context window and condenses the most important tokens for the lead — 0008's context economics as an organizational chart. The economics (memorize the shape)

  • It works: Opus 4 lead + Sonnet 4 workers beat single-agent Opus 4 by 90.2% on Anthropic's internal research eval — breadth-first queries with independent directions benefit most.
  • Why it works: on the BrowseComp eval, token usage alone explained 80% of performance variance (with tool-call count and model choice, three factors covered 95%). Multi-agent architectures are, bluntly, a machine for spending more tokens in parallel — and newer models multiply the value of each token.
  • What it costs: agents use ~4× the tokens of chat; multi-agent systems ~15×. "Economic viability requires tasks where the value of the task is high enough to pay for the increased performance."
  • When-not: tasks needing shared context across agents, or with heavy interdependencies — "most coding tasks involve fewer truly parallelizable tasks than research." When-yes: heavy parallelization, information exceeding single context windows, numerous complex tools.

The delegation craft

Anthropic's early failure modes are the exam's scenario seeds: agents spawning 50 subagents for simple queries, endless searches for nonexistent sources, duplicated work from vague instructions (two subagents redundantly investigating 2025 supply chains while one covered the 2021 chip crisis). The fixes:

  • Teach the orchestrator to delegate: every subagent task specifies an objective, output format, tool/source guidance, and task boundaries — 0011's description-driven delegation, with the stakes raised.
  • Scale effort to complexity (embedded as prompt rules): simple fact-finding = 1 agent, 3–10 tool calls; comparisons = 2–4 subagents, 10–15 calls each; complex research = 10+ subagents with divided responsibilities.
  • Parallelize twice: the lead spawns 3–5 subagents in parallel and subagents call 3+ tools in parallel — cutting research time up to 90%.
  • Start wide, then narrow: short broad queries first, then drill — agents otherwise default to long, over-specific queries that return nothing.
  • Let agents improve the tools: their tool-testing agent rewrote a flawed tool's description and cut future agents' task completion time by 40% — ACI as a self-improving loop.

Coordination, provenance, and the telephone game

The filesystem pattern — the appendix gem Subagents can write artifacts to a filesystem and pass lightweight references back to the coordinator, instead of funneling everything through conversation — "to minimize the game of telephone." Higher fidelity, fewer tokens, and outputs that outlive the run. Pair with: summarize completed phases to external memory; spawn fresh subagents with careful handoffs when contexts fill (0008's long-horizon playbook, confirmed at production scale).

Production realities

  • Errors compound. A minor failure can derail an agent's whole trajectory — so: durable execution, checkpoints and resume, never restart-from-zero. And "letting the agent know when a tool is failing… works surprisingly well" (0007's instructive errors, validated).
  • Evaluation can't be path-based — identical inputs legitimately take different paths. Judge outcomes and reasonable process; for state-mutating agents, evaluate end states at checkpoints. (0016 is entirely this.)
  • Deployment is delicate: agents mid-run can't all be swapped at once — Anthropic uses rainbow deployments, old and new versions running side by side as traffic shifts.
  • Emergent behavior: small orchestrator changes ripple into worker behavior unpredictably — the best prompts are "frameworks for collaboration… division of labor, problem-solving approaches, and effort budgets," not rigid scripts.
The win You can now design a multi-agent system with the full checklist: justify it with the economics (80% variance / 15× tokens), decompose with proper task descriptions, scale effort by complexity, parallelize at both levels, route artifacts through the filesystem, build provenance in (the citation stage), and plan for compounding errors with checkpoints and rainbow deploys.

Exercise — architect the due-diligence feature (exam-style)

Apex wants a "research this acquisition target" feature: given a company, produce a cited report covering market, financials, legal exposure, and tech stack — with a hard budget ceiling and a requirement that every claim carries its source.

On paper: (1) justify multi-agent (or argue against) using the economics; (2) write the task description for ONE subagent (all four elements); (3) apply effort scaling for "quick profile" vs "full deep-dive" tiers; (4) design the artifact/provenance flow; (5) state what happens when a subagent times out.

Check your answer

(1) Justified: breadth-first, four independent directions, sources exceeding any single context, high task value (an acquisition decision can pay 15× tokens). If the ask were "summarize this one filing," a single call wins.

(2) Model: "Objective: assess legal exposure for {company} — litigation, sanctions, regulatory actions. Output format: markdown findings file at /artifacts/legal.md, each claim followed by [source: URL]. Tools/sources: web_search broad-first, then narrow; prefer court records and regulators over SEO content farms. Boundaries: legal only — no financial or market analysis; stop at 12 tool calls." Objective, format, tools, boundaries — all four present.

(3) Quick profile: 1–2 subagents, 3–10 calls each. Deep-dive: 4+ subagents (one per area, divided responsibilities), 10–15 calls each — the embedded scaling rules, applied as product tiers.

(4) Workers write /artifacts/<area>.md with inline source attribution; the lead receives lightweight references, synthesizes; a final citation pass verifies every claim's [source: URL] — provenance as a pipeline stage, like Anthropic's CitationAgent.

(5) Checkpoint + resume, never restart: the lead learns the subagent failed (instructive error — 0007), re-spawns only that area with the task narrowed to what's missing, and the budget ceiling caps re-attempts. If your answer ended with the artifact files still on disk for the resumed run to reuse — you've internalized why the filesystem pattern exists.
