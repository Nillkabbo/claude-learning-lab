Asking well: plan mode and the prompt library

The difference between a magic demo and a mess is usually the prompt and the mode.

≈ 12 minutes + drill Claude Code Guide Hands-on by design
plan mode first

Plan mode first for anything big. Shift+Tab into plan, let Claude explore read-only, read the plan before a single edit (0009's pillar three). For small, well-understood changes, straight to work; for risky areas, manual mode so every action passes your eyes.

The official prompt library and best practices pages are the pattern book. The habits that hold up:

  • One task per prompt — compound asks produce compound messes.
  • Point at files ("in src/api/") instead of describing from memory.
  • Show the goal, not the surgery ("make the tests pass" beats step-by-step edit instructions).
  • Iterate in the session — feedback beats restarts; checkpointing has your back if an iteration goes wrong.
