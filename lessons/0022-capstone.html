Lesson 0022 · Phase 5 — Professional depth (final lesson of the phase)

Capstone: a full production architecture from a blank page

Twenty-one lessons, one checklist, one blank page. This is the exam, in slow motion.

≈ 20 minutes + the exercise Synthesizes 0001–0021 The exercise is the real lesson
the 11-line checklist

The CCAR exams give you a scenario and ask for judgment. This lesson compresses the entire course into the order you think in — a master checklist where every line is a decision you've already learned to make, cited to its lesson. Then the exercise hands you a blank page and a realistic brief. Do it on paper, under a timer if you can bear it.

The master checklist (design order)

  1. Criteria before architecture. Numeric success criteria, paired against gaming; constraint inventory; failure catalog with costs. 0019 · 0016
  2. Posture before patterns. Product chooser (who runs the loop?) and complexity ladder (single call → workflow → agent) — with the losing options' reasons recorded. 0012 · 0013
  3. Patterns composed, not worshiped. Route (focus/cost/privacy), chain with gates, section/vote, evaluate-and-refine; multi-agent only where the economics pay (parallel, context-exceeding, high-value). 0014 · 0015
  4. Interfaces designed for a reader. Structured outputs for shape (grammar/semantic/human validation layers); tools with four-question descriptions, enums, consolidation, high-signal results; strict: true where it matters. 0004 · 0006
  5. Errors and state engineered. Transient/permanent/uncertain classification; instructive messages; idempotency keys on side effects; verify-don't-retry. 0007
  6. Context budgeted. What counts, what re-bills; compaction and clearing with cache-aware thresholds; memory for what survives; tool-search if the tool bill is fat. 0008
  7. Trust boundaries drawn. Permission deny→ask→allow; confirmation gates in code (canUseTool); MCP scopes progressive, no passthrough, no session auth; untrusted content in tool_result blocks. 0009 · 0021
  8. The four workflow concerns. Escalation as a ≥95% skill with real handoff context; compliance in enforced layers; degradation ladder with no silent failures; paired business metrics. 0018
  9. Evaluation built before shipping. ~20-case starter set, graders from the spectrum judged cross-model, outcome-not-path for agents, humans for what automation misses. 0016
  10. The bill engineered. Batch the patient, cache the stable, tier the models, budget the thinking; invalidation hierarchy respected in release design. 0017
  11. The lifecycle owned. Handoff package (runbook = degradation ladder, why-ledger, eval suite, policy map); three-plane observation; iteration gated by evals, deployed by rainbow, protected by checkpoints. 0020

Your turn — the capstone

The brief: "Compass" for Meridian Bank (45–60 minutes, on paper)

Meridian Bank (500 analysts, regulated) wants Compass: analysts ask research questions answered from market data (already exposed as MCP tools by the bank), internal policy documents (large, static, updated weekly), and client portfolios (sensitive, access varies by analyst). Requirements: every claim cited; interactive answers in seconds; a nightly 200-question deep-research digest; advice compliance review; and a previous AI project that frightened the CFO's token budget.

Deliver, mapped to checklist numbers: (1) criteria + constraints + failure catalog; (2) posture with recorded reasons; (3) the architecture sketch — patterns per path; (4) interface decisions (one tool description outline, the structured-output choice); (5) error/idempotency design for portfolio writes; (6) the context strategy; (7) the trust map (MCP scopes, gates, content containment); (8) the four workflow concerns; (9) the eval plan; (10) the cost model with numbers; (11) the lifecycle package summary.

Check your answer against the model skeleton

(1) e.g. citation-accuracy ≥98% (compliance), interactive first-token p95 <2s, digest completeness per rubric ≥90%, sensitive-data exposure 0, CFO-facing monthly ceiling. Constraints: MCP market tools exist; policy docs static weekly; portfolio access per-analyst. Failure catalog: market-data outage, mid-write portfolio timeout, digest deadline miss.

(2) Interactive: routed workflow (no agent — latency is the product, paths are predictable). Digest: agent (open-ended, context-exceeding, high-value — the 15× economics can pay overnight). Posture: Agent SDK in the bank's perimeter (regulated data leaves nothing); Managed Agents rejected — recorded why.

(3) Interactive: classify → (policy-RAG lane | portfolio-tools lane | market lane) → chained draft → citation gate → emit; parallel screening vote on advice-adjacent outputs. Digest: orchestrator-workers — lead plans to memory, workers per question-cluster write filesystem artifacts, citation pass, end-state eval.

(4) Tools already exist via MCP: audit their descriptions against the four questions; consolidate overlaps; demand progressive scopes (market:read first). Structured outputs: the citation gate's schema and the digest's findings format; semantic rules (holdings freshness) validated in code.

(5) Portfolio writes: confirmation gate + idempotency key; timeout = uncertain → verify via read-back before retry; instructive errors to adapt.

(6) Interactive: stable-first prefix (policy corpus, tools) with breakpoints; per-analyst history as growing suffix. Digest: compaction + memory tool, clear_tool_uses with clear_at_least, thinking management on newer models.

(7) Portfolio lane = per-analyst scoped tools (no passthrough); market content stays in tool_result blocks; writes gated; digest workers sandboxed; scopes progressive, no wildcards.

(8) Escalation to human compliance reviewers with full context (artifacts, citations) on low-confidence advice; compliance = enforced filters + routing; degradation ladder per failure catalog (market outage → policy-only answers, honestly labeled); metrics paired (deflection ↔ analyst CSAT).

(9) ~20 real questions now; LLM-binary citation judge (cross-model), rubric judge on digests (0.0–1.0 + pass/fail), outcome-not-path for the digest agent; humans sample for source-selection bias.

(10) Digest via Batch (×0.5) where latency allows; cached policy prefix (reads ×0.1); tiered models by lane; tool bill audited; Tuesday-style tool changes scheduled against the invalidation hierarchy — show the CFO the arithmetic, not adjectives.

(11) Runbook from the ladder; why-ledger; eval suite in CI; usage-report dashboards by workspace/model; rainbow deploys; checkpoints for the overnight digest. If your paper hit all eleven with a number or spec-rule at each — you're ready for Phase 6's mocks.
