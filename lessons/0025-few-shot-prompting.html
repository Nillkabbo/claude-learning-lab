Few-shot prompting: showing, not telling

The exam's second-most-tested prompt-engineering skill — and the course's biggest gap, now closed.

≈ 12 minutes Exam: Prompt Engineering & Structured Output · 20% Task Statement 4.2

The official exam guide dedicates an entire task statement to this (4.2: "Apply few-shot prompting to improve output consistency and accuracy"), listing it among the most-tested skills. Yet the course has only mentioned it in passing. This lesson fixes that gap.

The consistency ladder: instructions alone → few-shot examples → schema-enforced. Few-shot is the middle rung.

What few-shot prompting is

Few-shot prompting means including 2–4 input/output examples in your prompt so the model can see the pattern you want, not just read about it. The official docs call examples "more effective than abstract instructions" — because the model pattern-matches from demonstrated behavior far better than it follows prose descriptions.

When to use it (the exam's three named scenarios)

ScenarioWhat you showWhy it works
Format consistency 2–3 input→output pairs in your exact target format The model copies the demonstrated shape, including nuances you'd never think to describe
Ambiguous classification Edge-case examples — one borderline input per class The model generalizes the boundary from examples it can't infer from the label alone
False-positive reduction Examples of inputs that should not match, alongside ones that should Negative examples are the cheapest precision fix — they show what to exclude

How to write good examples

  1. Use real data — your actual inputs, not synthetic placeholders. The model notices when examples are too clean.
  2. Show edge cases — one typical case + one boundary case beats four typical cases. The boundary is where the model needs help.
  3. Include a negative — an input where the correct output is "none" or the empty case. This is the official docs' top tip for reducing false positives.
  4. Keep it small — 2–4 examples. More than that and you're paying tokens for diminishing returns; fewer and the model may not generalize.
  5. Match your schema — if you're using structured outputs (0004), the examples should show the exact JSON shape you expect.
Few-shot + structured outputs (the exam combo) The exam's task statement 4.2 sits right next to 4.3 (structured outputs). The intended pairing: use few-shot examples to teach the model what to extract and the boundary cases, then use structured outputs to enforce how it comes out. Examples teach semantics; schemas enforce shape.

What few-shot is NOT

  • Not fine-tuning — you're not changing weights; you're showing the pattern in-context. Every request carries the examples.
  • Not a substitute for clear instructions — a good prompt has both: a clear instruction AND 2–3 examples. Examples disambiguate; they don't replace the ask.
  • Not free — examples consume input tokens on every request, and they invalidate your prompt cache if they change. Keep them stable.

Check yourself

Your turn

Exercise — fix the sentiment classifier

A teammate's sentiment classifier keeps flagging neutral statements as negative. The prompt is: "Classify each message as positive, negative, or neutral."

On paper: (1) write two few-shot examples that would fix this — include one borderline case and one negative example; (2) explain why each example targets the specific failure; (3) state what you'd add for structured-output enforcement.

Check your answer

(1) Borderline example: input: "The package arrived on Tuesday." → output: "neutral" (a factual statement with no emotional valence — this is the boundary case the classifier keeps getting wrong).
Negative example: input: "OK." → output: "neutral" (a terse acknowledgment that looks negative to a pattern-matcher but isn't).

(2) The first shows the positive↔neutral boundary (facts aren't positive). The second shows the negative↔neutral boundary (terse isn't hostile). Together they bracket the neutral zone from both sides.

(3) An enum-constrained structured output: {"sentiment": {"enum": ["positive", "negative", "neutral"]}} — the grammar guarantees the label is valid; the examples teach which label to pick.
