In which the third identical release teaches Claude to do it in one word.

Chapter 4 of 12 — the story so far.

Friday, again

Third Friday in a row. The release ritual: run the suite, bump the version, update the changelog, tag, push. Six steps, zero surprises, and — the part that finally breaks you — Priya watching you type them out by hand, twice.

"You know what a skill is?" she asks. You don't. "A procedure you write down once, with the discipline baked in, that becomes a command. Teach it the release."

The procedure becomes a word

First, the release needs something to release: close, from Priya's original spec, is still missing. One pointed ask, one read diff, done — python tracker.py close 3 marks a task done and list shows it struck through.

Then you create .claude/skills/release/SKILL.md:

---
description: Runs the full release ritual for Tracker. Use when asked to release or bump.
argument-hint: "[version, e.g. v0.2]"
allowed-tools: Bash(git *), Bash(python *)
---
Run the tests first; ABORT the release if any fail.
Then: bump the version in tracker.py, prepend a dated changelog entry to
CHANGELOG.md, commit with "release: <version>", tag the version, push with
tags. Announce nothing — I do that.

Every line is a decision you made once so you'd never make it badly at 4:55 p.m. again. The frontmatter does real work: argument-hint reminds Future You of the syntax; allowed-tools grants exactly the commands this ritual needs — a per-turn grant, gone with your next message, nothing permanent leaked.

Then: /release v0.2. Claude runs the suite — and aborts, because a test from your afternoon is red. The discipline you wrote down refuses to let you ship broken. You fix the test, run it again, and watch six steps happen correctly, fast, in order, while you drink your coffee like someone whose Fridays got 20 minutes longer.

What just happened, named A skill is institutional memory as an executable. The value isn't the typing saved — it's that the checks travel with the procedure. Your "abort if tests fail" line is a policy no busy Friday can forget.

Your turn — the chapter's hands-on

Do it in your real repo
  1. Add close (small pointed ask; read the diff).
  2. Create .claude/skills/release/SKILL.md with the frontmatter above, adapted to your repo.
  3. Break one test on purpose; run /release v0.2; watch it abort.
  4. Fix the test; re-run; verify the tag and changelog landed.

Checkpoint: close working, a real v0.2 released by your skill, one witnessed abort-on-red-test. Report it — next chapter, a test fails sometimes, and you'll need help looking in two places at once.
