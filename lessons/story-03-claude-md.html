Marco keeps asking

In which the same question, asked four times, gives birth to a file.

≈ 10 minutes + hands-on Concepts: CLAUDE.md · memory craft · /context · auto memory Project gains: a CLAUDE.md that onboards anyone

Week two: the pattern

Monday: "How do I run the tests?" — there are no tests. "How do I run it at all?" Tuesday: "Which Python are we on?" Wednesday: "Where do tasks live?" — in tasks.json, same as Monday. Thursday, Marco asks about the quotes bug again, and you watch Priya's eye twitch.

She doesn't snap. She writes one line on the whiteboard and underlines it twice:

Anything explained twice becomes documentation.

Then, to you: "Claude Code has a memory file. Make Marco unnecessary." Marco, delightfully unaware he's the villain of this chapter, says "cool."

The file is born

You run /init and Claude drafts a CLAUDE.md — accurate, generic, useless, three times longer than it needs to be. The craft, you realize, isn't generating one; it's cutting it down to what's true and load-bearing:

# Tracker

A tiny issue-tracker CLI. Python 3, stdlib only.

## Commands
- Run: `python tracker.py add|list|close ...`
- Data lives in `tasks.json` (atomic writes; corrupt input backs up, never destroys)

## Conventions
- One behavior per commit; conventional messages ("add: …", "fix: …")
- Write JSON atomically — temp file, then replace
- Test before asking for review

## Do not
- Add dependencies without asking Priya
- Commit tasks.json

Fifteen lines. Specific over vague ("Test before asking for review" beats "be careful"). And the section Priya insists on: Do not — because the file's real job isn't reminding what to do, it's preventing the mistakes your team actually makes.

What the file is — and is not

That evening you add a note to yourself, and it's the chapter's payload:

CLAUDE.md is context, not enforcement. It makes good behavior likely. It cannot make anything certain — "Do not commit tasks.json" is a convention here, and one day Chapter 7 will turn it into a real guardrail. Memory guides; rules enforce.

You also learn the scope ladder by living it: this file is the project scope — committed, shared, loud for everyone. Your own cross-project habits would live in ~/.claude/CLAUDE.md (user scope). A personal note about hating tabs would be CLAUDE.local.md — gitignored, yours. And when Claude keeps forgetting you prefer fix: prefixes? You stop re-typing it — that's the rule: same correction twice, it goes in the file.

Quietly, in the background, auto memory has been doing its own version of this — Claude's own notes about the project, loaded each session. You check everything with /context and see, for the first time, exactly what your sessions know: your fifteen lines, the auto-memory, the files open. What's loaded is what's real.

Friday proof

New contractor, first hour, zero questions about Python version or where data lives. Marco asks a new question — progress, of a kind. Priya reads the file, deletes one line you over-wrote, and says nothing, which from her is a standing ovation.

What Chapter 3 taught CLAUDE.md as team memory: under 200 lines, specific, with a Do-not section; the scope ladder (project / user / local); "explained twice → documented"; /context to audit what actually loads; and the law that will organize everything to come — memory is context, not enforcement.

Your turn — the chapter's hands-on

Do it in your real repo
  1. Run /init; then cut its output to ≤15 lines of what's true: run commands, conventions, and a Do not section with 2–3 real rules.
  2. Commit it.
  3. Start a fresh session; ask "what are this project's conventions?" — the answer should come from your file.
  4. Run /context; confirm CLAUDE.md is loaded; note the biggest token item.
  5. Catch yourself re-explaining something this week? Add it to the file — the twice-rule in action.

Checkpoint: a tight CLAUDE.md committed, proven loaded via /context, and a fresh session correctly answering "how do I run this?" Report it — in Chapter 4, a Friday chore gets so repetitive you teach Claude to do it with one word, and meet skills.
