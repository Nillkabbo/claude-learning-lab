CC-13 · Phase D — Team & enterprise

Settings at scale: scopes and managed policy

One product, many machines, one org — who wins, and on purpose.

≈ 12 minutes + drill Claude Code Guide Hands-on by design
managed > repo > local

0010's verified ladder at org size. Files: ~/.claude/settings.json (you, everywhere) → .claude/settings.json (repo, committed) → .claude/settings.local.json (you, this repo) → managed settings (org-deployed; nothing you set overrides it, with named security exceptions where stricter-locals win). Same key: highest level wins; permission lists merge.

  • Trust gating: allow rules from committed files apply only after each teammate trusts the folder; deny/ask apply immediately. First-day safety is a feature, not friction.
  • Strict JSON — comments and trailing commas mean a settings error; claude doctor lists rejected entries, /status shows sources.
  • Cloud sessions read committed + server-managed settings only — local files stay local.
