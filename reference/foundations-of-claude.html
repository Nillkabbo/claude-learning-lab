Foundations of Claude: the ten laws

Hold in every project, every product, every model generation. Learn these and nothing about Claude will surprise you.

The ten laws — three tiers: the contract (how it speaks), the engine (how it acts), the disciplines (how it ships).

  1. 1 · The API is stateless — you own the conversation

    Claude remembers nothing between requests. The messages array is the conversation, and your code must resend all of it, every call, ending with a user message. Every "the bot forgot" bug is a dropped turn; every long-chat cost is this law re-billing you. 0001

  2. 2 · Everything is content blocks

    A reply is a list of typed blocks — text, tool_use — not a string. That shape is what lets one response talk and act at once, and what you branch on. 0001 · 0005

  3. 3 · The system prompt is policy, not conversation — and it is context, not enforcement

    Role and standing rules live above the conversation; task content rides in user turns. And no prompt — system or memory file — guarantees anything: guarantees live in rules, filters, and gates. Newer models respond more strongly to system prompts, so shouted legacy rules now over-trigger. 0002 · 0009

  4. 4 · Shape is enforced by grammar; meaning by code; stakes by humans

    Structured outputs constrain generation itself (schema-valid by construction — though numerical constraints and length limits 400). Semantic rules are yours, post-parse. High-stakes or low-confidence outputs get human review. Three layers, three owners — never confuse them. Retired dials (temperature, prefill) are migration questions, not levers. 0003 · 0004

  5. 5 · The tool loop: the model requests, you execute, results ride in user messages

    stop_reason: tool_use → execute → tool_result in a user message, matched by tool_use_id, assistant turn echoed in full. Tool descriptions are the interface — "by far the most important factor in tool performance": what it does, when, when not, limits. 0005 · 0006

  6. 6 · Errors are messages the model reads

    Signal with is_error and instructive content. Transient says "retry after N"; permanent names the alternative; uncertain says UNKNOWN and demands verification — idempotency keys make retries safe by construction. MCP formalizes the split: protocol errors (communication) vs in-band execution errors (recoverable). 0007

  7. 7 · Context is a budget that rots

    Everything counts — messages, tool results, tool definitions, thinking, even cached tokens — and accuracy degrades as it grows. Compaction is the primary strategy; clearing is cache-aware; memory saves essentials before clearing. Curate, always. 0008

  8. 8 · Enforcement lives in layers

    Permission rules (deny → ask → allow, first match; lists merge; trust-gated) and deterministic filters enforce; hooks react (and fail open — use them for context and audit, not guarantees); prompts guide. Trust boundaries: untrusted content stays in tool_result blocks; MCP gives no token passthrough, no session auth, progressive scopes only. 0009 · 0021

  9. 9 · Complexity is a purchase

    "Find the simplest solution possible" — single call → workflow (route, chain with gates, section/vote, evaluate-and-refine) → agent (open-ended, ground truth per step, stopping conditions) → multi-agent (parallel, context-exceeding, high-value — ~15× tokens). Patterns compose; buy each rung only when it demonstrably pays. 0012 · 0013 · 0014 · 0015

  10. 10 · Evidence and economics gate everything

    Criteria before architecture, numeric. Evals gate every change (cross-model judges, outcomes not paths, humans for what automation misses). The bill is architecture: batch the patient (−50%), cache the stable (reads at 0.1×), respect the invalidation hierarchy. Then own it: handoff packages, three-plane observation, rainbow deploys. 0016 · 0017 · 0019 · 0020

How to use this page Before starting any project, walk the ten laws against your idea — each either changes a design decision or confirms one. Then open the build-anything playbook and execute it phase by phase, with the starter kit as your foundation in code.
